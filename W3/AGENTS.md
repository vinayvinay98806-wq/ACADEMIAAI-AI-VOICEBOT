# Developer & Contributor Guidelines: Worker 3 (W3 Context & Reasoning)

## 1. Scope & Ownership Boundaries

- **W3 Owner:** Context & Reasoning Team.
- **W3 Directory:** `w3_context_reasoning/` and `tests/`.
- **Upstream Boundaries:**
  - **W1 (Audio / STT):** Emits user transcriptions and audio events. W3 receives text utterances via W2 and never interacts with raw microphones or audio buffers directly.
  - **W2 (Session / Orchestrator):** Dispatches `ReasoningRequest` to W3 and receives `ReasoningResult`.
- **Downstream Boundaries:**
  - **W4 (TTS / Voice Output):** Receives grounded `response_text` from W2 (generated by W3) to synthesize voice output.

## 2. Invariants & Rules

1. **No External Network Calls in Mock Mode:**
   - Week 1 implementation must run 100% offline. Do not make network calls, invoke paid cloud APIs, or require API keys.
2. **Safe Capture Invariant:**
   - Real screen grabbing is strictly disabled by default (`capture_enabled=False`).
   - Any live screen capture attempt without synthetic flags must raise `InvalidRequestError`.
3. **Structural Prompt Trust Separation:**
   - Never concatenate untrusted user strings directly into system prompt instructions.
   - Always route prompt construction through `PromptManager.render_prompt(request)`.
4. **Validation Enforcement:**
   - All public methods must validate inputs via `validate_request()` and outputs via `validate_result()`.
   - Never reference ungrounded source IDs in `grounded_sources`.
5. **Git Policy:**
   - Work strictly within local workspace.
   - Do not push, pull, or modify remotes without explicit authorization.
